# 01 · 环境准备

> **目标**：让机器上具备跑 BnnBot 的全部前置条件。
> **做完的判据**：本篇最后一节的「自检」全部打 ✅。

---

## 1. 需要什么

| 组件 | 最低版本 | 为什么需要 | 检查命令 |
|---|---|---|---|
| **Node.js** | **`>= 24.9.0`** | DSH 本身硬要求（不是 BnnBot 要求的） | `node --version` |
| **pnpm** | `>= 9` | 装 link 依赖；用 npm 会出问题 | `pnpm --version` |
| **git** | 任意近期版本 | 拉仓库 | `git --version` |
| **DSH** | `>= 0.2.0-rc.2` | 宿主平台 | `dsh --version` |

> ⚠️ **最容易踩的坑**：网上很多「Node >= 20」的说法是针对 BnnBot 插件的。
> 但 **DSH 自己要求 Node >= 24.9.0**，Node 太老 `dsh` 直接起不来。
> 以 DSH 的要求为准。

---

## 2. 装 Node.js

### 有包管理器（Debian / Ubuntu / macOS / Termux）

```bash
# 先看现在是什么版本
node --version

# 如果 < v24.9.0，升级
```

**推荐用 nvm 或 fnm**（能装多版本，不污染系统）：

```bash
# fnm 示例
curl -fsSL https://fnm.vercel.app/install | bash
fnm install 24
fnm use 24
node --version    # 应显示 v24.x
```

### Android（Termux 环境）

Android 上的 DSH 自带一套 shell 环境，一般**不需要你手动装 Node**。
如果确实缺：

```bash
pkg install nodejs-lts
node --version
```

---

## 3. 装 pnpm

```bash
# 方式一：用 corepack（Node 自带）
corepack enable
corepack prepare pnpm@latest --activate

# 方式二：npm 全局装
npm install -g pnpm

# 验证
pnpm --version    # 应 >= 9
```

> **为什么必须用 pnpm**：BnnBot 插件是用 `link:` 方式挂进 DSH profile 的
> （`"dsh-bnnbotbox": "link:/path/to/dsh-bnnbotbox"`）。
> npm 对 `link:` 的支持有问题，会出现「装了但 DSH 找不到」。

---

## 4. 装 DSH

DSH 有两种装法。**手机上跑就用 APK（情况 A），最省事**。

### 情况 A：Android 手机（推荐，大多数人是这种）

DSH 的安卓壳是独立开源项目：

| 项 | 值 |
|---|---|
| 仓库 | <https://github.com/kelai141/dsh-mobile-apk> |
| 应用名 | **DeepCode** |
| 包名 | `com.dsharnessmobile.shell` |
| 系统要求 | **Android 8.0 及以上** |
| 安装包 | 约 150–160 MB，建议 Wi-Fi 下载 |
| 许可 | MIT |

**下载**：

- 下载页（自动选官方源/镜像）：<https://kelai141.github.io/dsh-mobile-apk/>
- 或 GitHub Releases：<https://github.com/kelai141/dsh-mobile-apk/releases/latest>

**选对架构（装错包会一启动就崩）**：

| 你的设备 | 选哪个包 |
|---|---|
| 真机（绝大多数手机） | **arm64** |
| 模拟器 / x86_64 设备 | **x86_64** |

> armv7l / 老机型**暂不支持**。

**安装步骤**：

1. 下载对应架构的 APK
2. 安装（或用 `adb install -r -t <apk>` 覆盖安装）
3. 打开 App，**首次启动会解压运行环境，可能要几分钟到十几分钟** —— 期间**别强杀**
4. 按引导给权限（无障碍、通知；Shizuku 可选，不装也能用）
5. 在**设置里配模型 API**（App 不内置任何模型服务）
6. 跑一条命令确认能通

**务必做的一件事**：把这个 App 加进**电池优化白名单**（应用内有引导）。
不加的话后台会被系统杀掉，机器人就掉线了。

> 📌 装好之后，App 自带 Node 和 DSH，**第 2、3 节的 Node/pnpm 检查可以跳过**（Termux 快照里已有）。
> 但如果你要在 App 的终端里 `git clone`、`pnpm add`，那些工具是齐的。

### 情况 B：命令行装（服务器 / NAS / 桌面 / 想自己控制环境）

```bash
npm install -g @deepseek-ai/dsh

# 验证
dsh --version
```

> 装完第一次跑 `dsh` 会引导你选 profile 和模型。**先把这一步走完**，
> 因为后面装 BnnBot 需要 profile 目录已经存在。

---

## 5. 搞清楚两个目录（很重要，后面全靠它）

BnnBot 的所有路径都从这两个地方推导。**先弄清楚它们在你这台机器上是哪**：

| 名字 | 是什么 | 典型位置 |
|---|---|---|
| **`DSH_HOME`** | DSH 的数据根 | Android：`~/.dsh`<br>Linux：`~/.dsh` |
| **`PROFILE_DIR`** | 当前 profile 目录，插件装这里 | `{DSH_HOME}/profiles/<名字>` |
| **工作区** | 你的项目目录（放人格、曲库） | 任意，比如 `/sdcard/DSH` 或 `~/bnnbot` |
| **qqbot `dataRoot`** | QQ 通道的数据根 | 通常 `{工作区}/Bot/dshqqbot` |

### 怎么查

```bash
# 如果 DSH 正在跑，环境变量里就有
echo "$DSH_HOME"
echo "$DSH_PROFILE_DIR"

# 没跑的话直接看目录
ls ~/.dsh/profiles/
```

> 📌 **记住这几个路径**。第 2 篇装插件、第 3 篇写配置都要用到它们。
> 后面文档里用 `{DSH_HOME}`、`{PROFILE_DIR}`、`{WORKSPACE}` 代指。

---

## 6. 推荐的工作区结构

不强制，但强烈建议照这个来（后面所有文档都按这个写）：

```
{WORKSPACE}/                       ← 比如 /sdcard/DSH 或 ~/bnnbot
└── Bot/
    ├── 人格/                       ← 人格卡、规则
    │   ├── 角色卡/
    │   │   └── 小忆.md            ← 内置人格（安装时自动生成）
    │   ├── 规则/
    │   └── persona-config.json    ← 当前用哪个人格
    ├── 曲库/                       ← 自备 mp3（可选）
    ├── 美图库/                     ← 自备图片（可选）
    ├── 事件库/                     ← 生活素材（可选）
    └── dshqqbot/                  ← 这是 qqbot 的 dataRoot
        ├── .qqbot/                 ← 通道数据（插件自己维护，不要手动改）
        └── extension-packs/        ← 扩展包放这里
            └── bnn-custom/
```

建目录（**只有工作区需要你手动建，其余安装时自动生成**）：

```bash
mkdir -p {WORKSPACE}/Bot/{人格/角色卡,曲库,美图库,事件库,dshqqbot/extension-packs}
```

## 7. 自检

逐个跑，全绿才继续：

```bash
# ① Node 版本必须 >= 24.9.0
node --version

# ② pnpm
pnpm --version

# ③ git
git --version

# ④ DSH
dsh --version

# ⑤ DSH 数据目录存在
ls -d "$DSH_HOME" 2>/dev/null || ls -d ~/.dsh

# ⑥ 工作区就绪
ls -d {WORKSPACE}/Bot
```

**期望结果**：

| 检查 | 期望 |
|---|---|
| `node --version` | `v24.9.0` 或更高 |
| `pnpm --version` | `9.x` 或更高 |
| `dsh --version` | 有输出（版本号 ≥ 0.2.0-rc.2） |
| `ls ~/.dsh` | 能看到 `profiles/` |

有任何一项不满足 → 先别往下走，把它解决掉。

## 附：Android 手机上的特殊情况

在 Android App 里跑 DSH 时，有几个和普通 Linux 不一样的地方：

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `/tmp` 不可写 | Android 沙盒限制 | 用 `os.tmpdir()` 或工作区下的临时目录 |
| `ln -s` 失败 | FUSE 不支持软链 | 用复制代替 |
| `tar czf` 失败 | 没有 gzip | 用 `cp -r` 备份 |
| 路径是 `/storage/emulated/0/...` | 共享存储 | 正常，别改成 `/sdcard` 以外的路径 |
| 后台被杀 | 系统省电策略 | App 设置里给它「无限制」后台 |

这些只影响**排障时的手段**，不影响正常运行。
